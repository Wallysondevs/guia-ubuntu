Ubuntu Projetos

Ler sobre comandos ensina a sintaxe. Montar algo de verdade ensina a usar os comandos juntos, a errar e a consertar. Cada projeto é um laboratório passo a passo: você monta um servidor, um backup ou uma aplicação numa máquina virtual que pode destruir e recriar quantas vezes quiser.

Você vai aprender
  • O que é uma máquina virtual de laboratório e por que nunca treinar na sua máquina principal.
  • Como criar, acessar, salvar e destruir uma VM com o Multipass.
  • Como ler um projeto: etapas, conferências e o que fazer quando algo dá errado.
  • Em que ordem fazer os cinco projetos.

Por que um laboratório?

Os projetos mexem em partes sensíveis do sistema: firewall, rede, discos, o arquivo /etc/fstab e permissões de administrador. Um erro nessas partes pode deixar um computador sem rede ou até sem ligar. Por isso, tudo acontece dentro de uma máquina virtual (VM, de virtual machine): um computador inteiro simulado dentro do seu.

Na sua máquina principalNa VM de laboratório
Um fstab errado impede o computador de ligarVocê restaura o ponto salvo em 30 segundos
Uma regra de firewall errada derruba a sua internetSó a VM fica sem rede
Encher o disco trava seus programasO disco da VM tem 10 GB e é descartável
Desfazer exige saber exatamente o que mudoumultipass delete --purge lab e recomeça do zero
Regras de segurança dos projetos
  • Nunca rode os desafios de Quebre e Conserte na sua máquina principal.
  • Antes de cada projeto, crie um ponto de restauração (snapshot) da VM.
  • Leia o comando inteiro antes de apertar Enter, principalmente os que começam com sudo.
  • Repare no prompt: ana@notebook é o seu computador, ubuntu@lab é a VM. Um comando no lugar errado faz estrago no lugar errado.

Instalar o Multipass

O Multipass é uma ferramenta da Canonical, a empresa que faz o Ubuntu, que cria VMs de Ubuntu com um comando. Ele vem como snap. Este comando roda no seu computador, o "notebook":

$ sudo snap install multipass
[sudo: authenticate] Senha:
multipass 1.16.1 from Canonical✓ installed           « o número da versão varia

Confira se ele está funcionando:

$ multipass version
multipass   1.16.1
multipassd  1.16.1
Outras opções

Se preferir uma VM com tela gráfica, use o VirtualBox ou o virt-manager e instale o Ubuntu Server a partir da ISO. Os projetos funcionam igual; só a criação e os snapshots mudam.

Criar a VM de laboratório

Primeiro, veja quais versões do Ubuntu o Multipass oferece. A coluna Aliases mostra os apelidos que você pode usar no lugar do número:

$ multipass find
Image                       Aliases           Version          Description
22.04                       jammy             20260930         Ubuntu 22.04 LTS
24.04                       noble             20260930         Ubuntu 24.04 LTS
26.04                       resolute,lts      20260930         Ubuntu 26.04 LTS     « use este
…

A saída acima é ilustrativa: datas e versões mudam com o tempo. Use o nome que aparecer para o 26.04.

multipass launch
Cria e liga uma VM nova.
26.04
A imagem: qual versão do Ubuntu instalar.
--name lab
O nome da VM. Também vira o nome da máquina no prompt.
--disk 10G
Tamanho do disco virtual: 10 GB.
--memory 2G
Memória RAM da VM: 2 GB.
$ multipass launch 26.04 --name lab --disk 10G --memory 2G
Launched: lab                                         « leva de 1 a 3 minutos na primeira vez
$ multipass list
Name                    State             IPv4             Image
lab                     Running           10.85.140.27     Ubuntu 26.04 LTS    « anote o IP

O IP da sua VM será outro. Ele é o endereço que você vai usar para acessar o servidor a partir do notebook.

Entrar na VM

$ multipass shell lab
Welcome to Ubuntu 26.04 LTS (GNU/Linux 7.0.0-14-generic x86_64)
…
ubuntu@lab:~$                                           « agora você está DENTRO da VM

Dentro da VM, o usuário padrão se chama ubuntu e tem sudo sem senha. Para voltar ao notebook, digite exit:

$ whoami
ubuntu
$ exit
logout
Por que as mensagens da VM aparecem em inglês?

As imagens do Multipass vêm configuradas com o idioma C.UTF-8, que é inglês. Por isso, dentro da VM você verá Permission denied no lugar de Permissão negada. Os projetos mostram as mensagens como elas aparecem lá.

Pontos de restauração (snapshots)

Um snapshot é uma "foto" da VM inteira. Se algo der errado, você volta para a foto e tudo fica como era. Tire um snapshot antes de cada projeto. A VM precisa estar desligada:

$ multipass stop lab
$ multipass snapshot lab --name limpo
Snapshot taken: lab.limpo
$ multipass start lab

Para voltar ao snapshot:

$ multipass stop lab
$ multipass restore --destructive lab.limpo
Snapshot restored: lab.limpo
$ multipass start lab

O --destructive diz ao Multipass para descartar o estado atual sem perguntar se você quer salvá-lo antes.

Como ler um projeto

Todo projeto tem o mesmo formato:

  1. O que vamos fazer e por quê: a ideia da etapa antes dos comandos.
  2. Comandos: numa janela de terminal. Repare no prompt para saber onde rodar.
  3. Saída esperada: o que deve aparecer, com as partes importantes explicadas.
  4. Confira se deu certo: um comando que prova que a etapa funcionou. Não pule.
  5. Se deu errado: os erros mais comuns daquela etapa e como resolver.

Quando não funciona

"multipass: comando não encontrado" 
$ multipass list
multipass: comando não encontrado

O que aconteceu: o Multipass não está instalado, ou o terminal foi aberto antes da instalação.

Como resolver: rode sudo snap install multipass. Se já instalou, feche e abra o terminal de novo.

A imagem 26.04 não é encontrada

O que aconteceu: o nome da imagem foi digitado errado (por exemplo, 26.4), ou sua versão do Multipass é antiga e ainda não conhece essa imagem.

Como resolver: rode multipass find e use exatamente o nome ou apelido mostrado. Atualize o Multipass com sudo snap refresh multipass.

A VM não tem IP ou o launch demora demais

O que aconteceu: a VM pode não ter terminado de iniciar, ou o firewall do notebook está bloqueando a rede virtual do Multipass.

Como confirmar: multipass info lab mostra o estado. Se estiver Running sem IP, espere um minuto e repita.

Como resolver: se o notebook usa ufw, veja se ele não está bloqueando a interface mpqemubr0. Em último caso, apague e recrie a VM.

Resumo

  • Projetos são feitos numa VM descartável, nunca na máquina principal.
  • multipass launch 26.04 --name lab --disk 10G --memory 2G cria a VM; multipass shell lab entra nela.
  • O prompt diz onde você está: ana@notebook (seu PC) ou ubuntu@lab (VM).
  • Snapshots são pontos de restauração: tire um antes de cada projeto.
  • multipass delete --purge lab apaga tudo para recomeçar.
