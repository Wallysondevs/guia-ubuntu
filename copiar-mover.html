Ubuntu cp e mv

cp copia e mv move. O mv também serve para renomear, porque, para o Linux, renomear é "mover para um nome novo". Os dois funcionam do mesmo jeito: primeiro de onde, depois para onde.

Você vai aprender
  • A regra "origem → destino" e como o destino muda o resultado.
  • Copiar um arquivo, vários arquivos e pastas inteiras.
  • Renomear e mover com mv.
  • Evitar sobrescrever arquivos por acidente (-i, -n, backups).
  • O que fazer com "-r não especificado", "Não é um diretório" e outros erros.

A ideia: origem primeiro, destino por último

Os dois comandos seguem a mesma ordem. Leia como uma frase: "copie isto para lá".

cp  ORIGEM...  DESTINO
mv  ORIGEM...  DESTINO

O último argumento é sempre o destino. O que acontece depende do que é o destino:

O destino é…ResultadoExemplo
Uma pasta que existeO arquivo vai para dentro dela, com o mesmo nomecp notas.txt Downloads/
Um nome que não existeCria um arquivo novo com esse nomecp notas.txt notas-copia.txt
Um arquivo que existeSubstitui o conteúdo, sem perguntarcp novo.txt velho.txt
Termine pastas com /

Escreva cp notas.txt Downloads/ em vez de Downloads. Se a pasta não existir, a barra faz o comando dar erro em vez de criar um arquivo chamado "Downloads".

cp: copiar um arquivo

cp vem de copy, "copiar". O original continua onde estava.

cp
O programa que copia.
notas.txt
A origem: o que copiar.
notas-copia.txt
O destino: como a cópia vai se chamar.
$ cp notas.txt notas-copia.txt
$ ls
acesso.log  notas-copia.txt  notas.txt  projetos  relatorio.odt

Como sempre no Linux, o cp não falou nada: deu certo. Para ele contar o que fez, use -v (verbose, "detalhado"):

$ cp -v notas.txt ~/Downloads/
'notas.txt' -> '/home/ana/Downloads/notas.txt'      « origem -> destino

Copiar vários arquivos de uma vez

Com mais de uma origem, o destino precisa ser uma pasta:

cp
O programa.
-v
Mostra cada cópia.
notas.txt relatorio.odt
Duas origens.
~/Downloads/
O destino, uma pasta. É sempre o último argumento.
$ cp -v notas.txt relatorio.odt ~/Downloads/
'notas.txt' -> '/home/ana/Downloads/notas.txt'
'relatorio.odt' -> '/home/ana/Downloads/relatorio.odt'

Missão: você está em Documentos. Faça uma cópia de notas.txt chamada notas-bkp.txt aqui mesmo, e outra cópia dentro de ~/Downloads. Confira com ls.

Copiar pastas: -r

Tente copiar uma pasta do jeito normal:

$ cp projetos projetos-bkp
cp: -r não especificado; omitindo o diretório 'projetos'

O cp se recusa: copiar uma pasta significa copiar tudo o que está dentro dela, e ele quer que você peça isso explicitamente. A opção é -r (de recursive, "recursivo"):

$ cp -rv projetos projetos-bkp
'projetos' -> 'projetos-bkp'
'projetos/backup.sh' -> 'projetos-bkp/backup.sh'
'projetos/site' -> 'projetos-bkp/site'
'projetos/site/index.html' -> 'projetos-bkp/site/index.html'
'projetos/site/style.css' -> 'projetos-bkp/site/style.css'

Cuidado: o destino existir muda o resultado

Se projetos-bkp não existe, ele vira a cópia. Se já existe, a cópia vai para dentro dele, como projetos-bkp/projetos. Rodar o mesmo comando duas vezes dá resultados diferentes:

$ cp -r projetos projetos-bkp
$ cp -r projetos projetos-bkp
$ ls projetos-bkp
backup.sh  projetos  site                 « na 2ª vez, foi parar dentro

Preservar dono, permissões e datas: -a

A cópia normal ganha a data de agora e passa a ser sua. Para uma cópia idêntica (útil em backups), use -a (de archive, "arquivar"), que já inclui o -r:

$ cp -a Documentos /media/ana/BACKUP/

mv: mover e renomear

mv vem de move, "mover". Diferente do cp, o original deixa de existir no lugar antigo. E ele move pastas sem precisar de -r.

Renomear

Renomear é mover para um nome novo, na mesma pasta:

mv
O programa.
notas-copia.txt
O nome atual.
rascunho.txt
O nome novo.
$ mv -v notas-copia.txt rascunho.txt
renomeado 'notas-copia.txt' -> 'rascunho.txt'

Mover para outra pasta

$ mv -v rascunho.txt ~/Downloads/
renomeado 'rascunho.txt' -> '/home/ana/Downloads/rascunho.txt'

A mensagem do -v diz "renomeado" nos dois casos, porque para o sistema é a mesma operação.

Mover e renomear de uma vez

$ mv -v manual.pdf ~/Documentos/manual-impressora.pdf
renomeado 'manual.pdf' -> '/home/ana/Documentos/manual-impressora.pdf'

Missão: você está em Downloads. Mova foto.jpg para a pasta Imagens, já com o nome foto-perfil.jpg, num único comando.

Não sobrescrever por acidente

Por padrão, cp e mv substituem o destino sem perguntar. O conteúdo antigo é perdido, sem lixeira. Há três formas de se proteger:

1. Perguntar antes: -i

-i (de interactive, "interativo") pergunta antes de substituir. Responda s para sim ou n para não.

$ cp -i ~/Downloads/notas.txt notas.txt
cp: sobrescrever 'notas.txt'? n                    « nada foi alterado

2. Nunca substituir: --update=none

Para pular, sem perguntar, os arquivos que já existem no destino, use --update=none. A forma antiga, -n, ainda funciona, mas no Ubuntu 26.04 o cp avisa que ela pode mudar:

$ cp -n notas.txt ~/Downloads/
cp: warning: behavior of -n is non-portable and may change in future; use --update=none instead
$ cp --update=none notas.txt ~/Downloads/

3. Guardar o antigo: -b e cópia manual

Com -b (backup), o cp renomeia o arquivo antigo antes de substituir. Mas o hábito mais seguro é fazer a cópia você mesmo antes de editar qualquer arquivo importante:

#> cp -v /etc/hosts /etc/hosts.bak
'/etc/hosts' -> '/etc/hosts.bak'

Se a edição der errado, basta cp /etc/hosts.bak /etc/hosts. Você vai usar muito esse truque com arquivos de /etc.

Copiar só o que mudou: -u

-u (de update) só copia quando a origem é mais nova que o destino. É um "sincronizar" simples. Para sincronizar pastas grandes, o rsync é melhor (veja scp e rsync).

Quando não funciona

"-r não especificado; omitindo o diretório" 
$ cp projetos /tmp/
cp: -r não especificado; omitindo o diretório 'projetos'

O que aconteceu: você tentou copiar uma pasta sem -r. Nada foi copiado.

Como resolver: cp -r projetos /tmp/.

"não foi possível obter estado de…" 
$ cp Notas.txt /tmp/
cp: não foi possível obter estado de 'Notas.txt': Arquivo ou diretório inexistente

O que aconteceu: a origem não existe. "Obter estado" é o jeito técnico de dizer "olhar o arquivo". Aqui, o N maiúsculo está errado.

Como resolver: confira com ls e use o Tab.

"alvo: Não é um diretório" ou "Arquivo ou diretório inexistente" 
$ cp notas.txt acesso.log relatorio.odt
cp: alvo 'relatorio.odt': Não é um diretório
$ mv notas.txt acesso.log backup
mv: alvo 'backup': Arquivo ou diretório inexistente

O que aconteceu: com várias origens, o último argumento precisa ser uma pasta que existe. No primeiro caso é um arquivo; no segundo, a pasta backup não existe.

Como resolver: crie a pasta antes (mkdir backup) e confira se o destino é mesmo o último argumento.

"Permissão negada" 
$ cp notas.txt /etc/
cp: não foi possível criar arquivo comum '/etc/notas.txt': Permissão negada

O que aconteceu: você não pode escrever em /etc.

Como resolver: se realmente for necessário, sudo cp notas.txt /etc/. Veja sudo.

Substituí um arquivo sem querer

O que aconteceu: o destino já existia, e cp/mv substituíram sem perguntar.

Como resolver: o conteúdo antigo não vai para a lixeira. Só um backup pode trazê-lo de volta. Para não acontecer de novo, use -i ou crie o atalho alias cp='cp -i' e alias mv='mv -i' no ~/.bashrc (veja .bashrc, alias, PATH).

Resumo

  • cp origem destino copia; mv origem destino move ou renomeia. O destino é sempre o último.
  • Para copiar pastas, use -r (ou -a para uma cópia idêntica). O mv move pastas sem opção.
  • Os dois substituem o destino sem perguntar. Use -i, --update=none ou faça um .bak antes.
  • -v mostra o que foi feito. Sem ele, silêncio significa sucesso.
