Ubuntu Atualizações

Manter o sistema atualizado é a medida de segurança mais importante que existe, e no Ubuntu ela leva um minuto. Nesta aula você vai montar uma rotina de atualização, entender o que o Ubuntu já faz sozinho, saber quando é preciso reiniciar e como passar para uma versão nova do Ubuntu.

Você vai aprender
  • Os três tipos de atualização e com que frequência fazer cada um.
  • A rotina completa: apt, snap e flatpak.
  • O que é o "faseamento" e por que alguns pacotes ficam para depois.
  • Como funcionam as atualizações automáticas de segurança.
  • Como saber se precisa reiniciar, e como atualizar para a próxima versão do Ubuntu.

Antes, leia apt e Snap.

A rotina semanal

Quatro comandos cobrem tudo o que está instalado:

$ sudo apt update
$ sudo apt upgrade
$ sudo snap refresh
$ flatpak update
ComandoO que faz
sudo apt updateBaixa a lista atualizada dos pacotes.
sudo apt upgradeInstala as versões novas dos pacotes do apt.
sudo snap refreshAtualiza os snaps (eles também se atualizam sozinhos).
flatpak updateAtualiza os flatpaks, se você usar (veja Flatpak).

Tudo numa linha

sudo apt update
Atualiza a lista…
&&
…e, só se deu certo, segue para o próximo.
sudo apt upgrade -y
Atualiza os pacotes, respondendo "sim" sozinho.
&& sudo snap refresh
Por fim, os snaps.
$ sudo apt update && sudo apt upgrade -y && sudo snap refresh

Para não digitar isso toda vez, você pode criar um atalho (alias) chamado atualizar no seu ~/.bashrc. Veja .bashrc, alias, PATH.

Pela interface gráfica

O app Atualizador de Programas faz o mesmo que o apt update + apt upgrade, com botões. O Ubuntu o abre sozinho quando há atualizações. Os snaps se atualizam em segundo plano e, quando um app está aberto, aparece uma notificação pedindo para fechá-lo.

Faseamento: "Ainda não atualizando"

Às vezes, o apt upgrade deixa pacotes de fora:

$ sudo apt upgrade
Ainda não atualizando devido ao faseamento:
  mesa-opencl-icd  mesa-vulkan-drivers

Resumo:
  Atualizando: 0, Instalando: 0, Removendo: 0, Não atualizando: 2

Isso é normal. O Ubuntu libera algumas atualizações aos poucos, primeiro para uma parte dos computadores (o faseamento, em inglês phased updates). Se aparecer algum problema, a atualização é suspensa antes de chegar a todo mundo. Em alguns dias ela chega à sua máquina.

Não force

Não tente instalar esses pacotes "na marra" com apt install. Esperar é exatamente o que protege você de uma atualização com defeito.

Atualizações automáticas de segurança

O Ubuntu vem com o unattended-upgrades ("atualizações não assistidas") ligado. Uma vez por dia, ele baixa a lista de pacotes e instala sozinho as atualizações de segurança. As outras ficam para você.

A configuração fica num arquivo pequeno:

$ cat /etc/apt/apt.conf.d/20auto-upgrades
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Download-Upgradeable-Packages "0";
APT::Periodic::AutocleanInterval "0";
APT::Periodic::Unattended-Upgrade "1";
LinhaSignificado
Update-Package-Lists "1"Faz o equivalente a apt update a cada 1 dia.
Download-Upgradeable-Packages "0"Não baixa antecipadamente as outras atualizações.
AutocleanInterval "0"Não limpa o cache de pacotes automaticamente.
Unattended-Upgrade "1"Instala as atualizações de segurança a cada 1 dia.

Para ligar ou desligar com uma pergunta simples (sim/não):

$ sudo dpkg-reconfigure unattended-upgrades

O que ele fez?

O registro fica em /var/log/unattended-upgrades/:

$ tail -3 /var/log/unattended-upgrades/unattended-upgrades.log
2026-10-15 08:14:17,844 INFO Lista de permissões inicial (not strict):
2026-10-15 08:14:20,072 INFO Sem pacotes encontrados que podem ser atualizados sozinhos e sem dependendo de auto-remoções
2026-10-15 08:14:20,194 INFO Package mesa-opencl-icd is kept back because a related package is kept back or due to local apt_preferences(5).

A segunda linha diz que, nesse dia, não havia nenhuma atualização de segurança pendente. A tradução tem erros e mistura inglês, mas é a saída real.

Por que o apt às vezes está "travado" de manhã

Enquanto o unattended-upgrades trabalha, ele segura a trava do apt. Se você tentar instalar algo nesse momento, recebe "Ela está sendo mantida pelo processo … (unattended-upgr)". Espere alguns minutos. Veja apt.

Precisa reiniciar?

A maioria das atualizações vale assim que termina. Algumas, como as do kernel (o núcleo do sistema) e de bibliotecas básicas, só passam a valer depois de reiniciar. Quando isso acontece, o Ubuntu cria um arquivo-aviso:

$ cat /var/run/reboot-required
*** System restart required ***
$ cat /var/run/reboot-required.pkgs
linux-image-7.0.0-40-generic
linux-base

O primeiro arquivo diz "é preciso reiniciar"; o segundo diz por causa de quais pacotes. Se o arquivo não existe, não precisa:

$ cat /var/run/reboot-required
cat: /var/run/reboot-required: No such file or directory

No desktop, o Atualizador de Programas mostra um aviso com o botão Reiniciar agora.

Qual kernel está rodando?

$ uname -r
7.0.0-38-generic                             « o kernel em uso agora

Se você acabou de instalar o 7.0.0-40 e o uname -r ainda mostra 38, falta reiniciar.

Atualizar para uma nova versão do Ubuntu

As versões LTS saem a cada dois anos, em abril dos anos pares (24.04, 26.04…). Por padrão, o Ubuntu oferece passar de uma LTS para a próxima LTS, a partir da primeira atualização pontual (por exemplo, 26.04.1).

sudo
Mexe no sistema inteiro.
do-release-upgrade
"Faça a atualização de versão": procura uma versão nova e conduz a troca.
$ sudo do-release-upgrade
Checking for a new Ubuntu release
No new release found.

"No new release found" (nenhuma versão nova encontrada) significa que você já está na mais recente para a sua política. Que versões são oferecidas fica em /etc/update-manager/release-upgrades, na linha Prompt=lts.

Antes de atualizar a versão
  • Faça backup dos seus arquivos.
  • Rode antes sudo apt update && sudo apt full-upgrade e reinicie.
  • Use uma conexão estável e deixe o notebook na tomada. A troca leva de 30 minutos a algumas horas.
  • PPAs e repositórios de terceiros são desativados durante a troca. Reative depois, se houver versão para o Ubuntu novo.

Ubuntu Pro e Livepatch

O Ubuntu Pro estende as atualizações de segurança de uma LTS para até 10 anos, inclusive para os pacotes do repositório universe. Para uso pessoal, é gratuito em até 5 máquinas: basta uma conta Ubuntu One e o token do site ubuntu.com/pro.

$ sudo pro attach SEU_TOKEN
$ pro status
SERVICE          ENTITLED  STATUS       DESCRIPTION
esm-apps         yes       enabled      Expanded Security Maintenance for Applications
esm-infra        yes       enabled      Expanded Security Maintenance for Infrastructure
livepatch        yes       enabled      Canonical Livepatch service

A saída é ilustrativa. O Livepatch, incluído no Pro, aplica correções de segurança no kernel sem reiniciar.

Os comandos desta página não rodam no terminal simulado. Pratique numa máquina virtual.

Quando não funciona

"Os pacotes a seguir serão mantidos em suas versões atuais"

O que aconteceu: o upgrade não instala atualizações que exigem remover ou adicionar pacotes, como uma troca de kernel ou de driver.

Como resolver: se não for faseamento, rode sudo apt full-upgrade e leia a lista antes de confirmar.

"Não há espaço disponível no dispositivo" durante a atualização

O que aconteceu: o disco, ou a partição /boot, encheu. Kernels antigos acumulados costumam ser a causa.

Como resolver: veja o espaço com df -h, rode sudo apt autoremove (que remove kernels antigos) e sudo apt clean. Depois, sudo apt --fix-broken install. Veja lsblk, df, du.

A atualização foi interrompida 
$ sudo apt upgrade
Erro: dpkg foi interrompido, você deve executar manualmente 'sudo dpkg --configure -a' para corrigir o problema.

O que aconteceu: a energia caiu, ou você fechou o terminal no meio de uma instalação.

Como resolver: rode exatamente o sugerido, sudo dpkg --configure -a, e depois sudo apt --fix-broken install.

Uma atualização quebrou um programa

Como resolver: se for snap, sudo snap revert nome volta na hora. Se for do apt, veja as versões disponíveis com apt policy nome. Se o problema for o kernel, escolha o kernel anterior no menu do GRUB, que aparece segurando Shift (ou apertando Esc) ao ligar. Veja Boot, GRUB e Kernel.

Resumo

  • Segurança: automática todo dia. Correções: apt update && apt upgrade + snap refresh toda semana. Versão nova: do-release-upgrade a cada LTS.
  • Pacotes "não atualizando devido ao faseamento" chegam sozinhos: não force.
  • /var/run/reboot-required existe quando é preciso reiniciar.
  • Antes de trocar de versão: backup, full-upgrade e tomada.
