Ubuntu Docker

O Docker roda programas dentro de containers: caixas isoladas que já trazem tudo o que o programa precisa. Com ele você sobe um servidor web, um banco de dados ou um app inteiro com um comando, sem bagunçar o seu sistema, e apaga tudo com outro comando.

Você vai aprender
  • A diferença entre container, imagem e máquina virtual.
  • As duas formas de instalar o Docker no Ubuntu, e qual escolher.
  • O que cada parte de docker run -d -p 8080:80 --name web nginx faz.
  • Como guardar dados fora do container com volumes.
  • Como criar a sua própria imagem com um Dockerfile.
  • O que fazer com "permission denied", "port is already allocated" e container que morre na hora.

Os exemplos acontecem na máquina fictícia notebook, usuária ana. As saídas do Docker mudam um pouco entre versões (IDs, tamanhos, números de versão): trate-as como ilustrativas.

Conceito: imagem, container e VM

Três palavras aparecem o tempo todo. Pense numa receita de bolo:

Usar sem sudo: o grupo docker

O comando docker conversa com o serviço por um arquivo especial, o socket /var/run/docker.sock. Só o root e quem está no grupo docker podem usá-lo. Sem isso, você vê:

$ docker ps
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock: Get "http://%2Fvar%2Frun%2Fdocker.sock/v1.47/containers/json": dial unix /var/run/docker.sock: connect: permission denied
sudo usermod
Altera uma conta de usuário (veja Usuários e Grupos).
-aG docker
-a = acrescentar, -G docker = ao grupo docker. Sem o -a, você sairia dos outros grupos (inclusive do sudo).
$USER
Variável com o seu nome de usuário (ana).
$ sudo usermod -aG docker $USER
$ groups
ana adm cdrom sudo dip plugdev users lpadmin   « docker ainda não aparece
$ newgrp docker
$ groups
docker adm cdrom sudo dip plugdev users lpadmin ana
$ docker ps
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES   « funcionou (lista vazia)

O grupo novo só vale em sessões novas. O newgrp docker resolve no terminal atual; para valer em tudo, saia da sessão e entre de novo.

Atenção: grupo docker = poder de root

Quem está no grupo docker pode montar o disco inteiro dentro de um container e mexer em qualquer arquivo do sistema. Em servidores com várias pessoas, coloque no grupo só quem já teria sudo. Uma alternativa mais segura é o modo rootless do Docker.

O que o comando devolve

docker run devolve o código de saída do programa de dentro do container. Isso permite usar containers em scripts:

$ docker run --rm ubuntu true
$ echo $?
0
$ docker run --rm ubuntu false
$ echo $?

$ docker run --rm ubuntu comando-que-nao-existe

$ echo $?

Um servidor de verdade: nginx

Agora um container que fica rodando: o servidor web nginx. É aqui que entram as opções mais usadas.

docker run
Cria e roda um container.
-d

-p 8080:80

--name web
Um nome fácil. Sem ele, o Docker inventa um (ex.: quirky_lovelace).

Container descartável: --rm

Com docker run --rm, o container é apagado sozinho quando termina. Use para testes rápidos, como docker run --rm -it ubuntu:26.04 bash, que abre um Ubuntu limpo para brincar.

Guardar dados: volumes

Tudo o que um programa grava dentro do container some quando o container é apagado. Para guardar dados, ligue uma pasta de fora a uma pasta de dentro. Há duas formas:

Forma 1: pasta do Ubuntu (bind mount)

-v ~/site:/usr/share/nginx/html
pasta-do-ubuntu:pasta-do-container. O que você muda em ~/site aparece na hora no container.
:ro
Opcional: read-only, o container só pode ler.
$ mkdir ~/site
$ echo "<h1>Site da Ana</h1>" > ~/site/index.html
$ docker run -d -p 8080:80 --name web -v ~/site:/usr/share/nginx/html:ro nginx
$ curl localhost:8080
<h1>Site da Ana</h1>                         « o nginx serve o arquivo do seu Ubuntu

Forma 2: volume gerenciado pelo Docker

$ docker volume create dados-db
dados-db
$ docker run -d --name db -e POSTGRES_PASSWORD=segredo -v dados-db:/var/lib/postgresql/data postgres:17
$ docker volume ls
DRIVER    VOLUME NAME
local     dados-db
FormaExemploMelhor quando…
Pasta do Ubuntu-v ~/site:/dadosVocê quer editar os arquivos (código, site, configurações).
Volume nomeado-v dados-db:/dadosOs dados são do programa (banco de dados) e você não mexe à mão.
Sem volume(nada)Os dados podem sumir (testes).

Sua própria imagem: Dockerfile

Um Dockerfile é a receita da imagem: um arquivo de texto com uma instrução por linha. Exemplo: um site estático servido pelo nginx.

# Parte de uma imagem pronta (a "base")
FROM nginx:1.29-alpine

# Copia os arquivos do projeto para dentro da imagem
COPY site/ /usr/share/nginx/html/

# Documenta a porta que o programa usa
EXPOSE 80

# (o nginx já define o comando de partida; não é preciso CMD aqui)
InstruçãoO que faz
FROMImagem base. Toda receita começa daqui.
RUNRoda um comando durante a construção (ex.: RUN apt-get update && apt-get install -y curl).
COPYCopia arquivos do projeto para dentro da imagem.
WORKDIRDefine a pasta de trabalho dentro da imagem.
ENVDefine variáveis de ambiente.
EXPOSEDocumenta a porta. Não publica nada: isso é o -p.
CMDO comando que roda quando o container sobe.
docker build
Constrói uma imagem a partir de um Dockerfile.
-t meusite:1.0
tag: o nome e a versão da imagem nova.
.
O "contexto": a pasta atual, onde estão o Dockerfile e a pasta site/.
$ ls
Dockerfile  site
$ docker build -t meusite:1.0 .
[+] Building 3.2s (7/7) FINISHED
 => [internal] load build definition from Dockerfile
 => [1/2] FROM docker.io/library/nginx:1.29-alpine
 => [2/2] COPY site/ /usr/share/nginx/html/
 => exporting to image
 => => naming to docker.io/library/meusite:1.0
$ docker run -d -p 8081:80 --name meusite meusite:1.0

Quando não funciona

"permission denied while trying to connect to the Docker daemon socket"

O que aconteceu: seu usuário não está no grupo docker, ou entrou nele e ainda não abriu uma sessão nova.

Como confirmar: groups não mostra docker.

Como resolver: sudo usermod -aG docker $USER e depois saia e entre na sessão (ou use newgrp docker).

"Cannot connect to the Docker daemon … Is the docker daemon running?" 
$ docker ps
Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
$ systemctl is-active docker
inactive

Como resolver: sudo systemctl enable --now docker. Se não subir, veja o motivo em journalctl -u docker -n 30 (veja Logs).

"port is already allocated" 
$ docker run -d -p 8080:80 --name web2 nginx
docker: Error response from daemon: driver failed programming external connectivity on endpoint web2 (3c1e…): Bind for 0.0.0.0:8080 failed: port is already allocated.

O que aconteceu: outro container (ou outro programa) já usa a porta 8080 do Ubuntu.

Como confirmar: docker ps e sudo ss -tulpn | grep 8080 (veja ss).

Como resolver: escolha outra porta do lado do Ubuntu (-p 8081:80) ou pare o outro container. O container web2 foi criado mesmo assim, parado: apague com docker rm web2.

O container morre na hora 
$ docker run -d --name teste ubuntu
5d2a…
$ docker ps
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES     « vazio!
$ docker ps -a
CONTAINER ID   IMAGE    COMMAND       CREATED          STATUS                      PORTS   NAMES
5d2a8f1e7c33   ubuntu   "/bin/bash"   10 seconds ago   Exited (0) 9 seconds ago            teste

O que aconteceu: um container vive enquanto o programa principal dele vive. A imagem ubuntu roda bash, que sem terminal termina na hora.

Como resolver: para usar interativamente, rode com -it: docker run -it ubuntu. Se for um app seu que morre, leia o motivo com docker logs teste.

"pull access denied" ou "not found" 
$ docker run nginxx
Unable to find image 'nginxx:latest' locally
docker: Error response from daemon: pull access denied for nginxx, repository does not exist or may require 'docker login'.

O que aconteceu: erro de digitação no nome da imagem, ou uma tag que não existe. Confira o nome no Docker Hub.

Atenção: o Docker e o firewall

Portas publicadas com -p passam por regras próprias do Docker e podem ficar acessíveis mesmo com o ufw bloqueando. Para publicar só para a própria máquina, use -p 127.0.0.1:8080:80.

Resumo

  • Imagem é a receita, container é a imagem rodando.
  • Instale com sudo apt install docker.io docker-compose-v2 e entre no grupo docker, sabendo que ele equivale a root.
  • docker run -d -p HOST:CONTAINER --name NOME IMAGEM é a forma mais usada.
  • ps, logs, exec -it, stop, rm são o dia a dia.
  • Dados importantes vão em volumes (-v); sem isso, somem com o container.
  • Um Dockerfile descreve a sua própria imagem, e docker build -t a constrói.
