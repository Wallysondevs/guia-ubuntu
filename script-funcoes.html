Ubuntu Funções

Uma função é um bloco de comandos com nome. Você escreve uma vez e chama quantas vezes quiser, como se fosse um comando novo. Funções deixam scripts grandes organizados em partes pequenas, cada uma com um trabalho só.

Você vai aprender
  • Como definir e chamar uma função, e passar argumentos para ela.
  • A diferença entre return (código de saída) e echo (resultado).
  • Por que usar local nas variáveis da função.
  • Como reaproveitar funções com source e fazer limpeza automática com trap.
  • Como organizar um script real inteiro em funções.

Antes, leia Condicionais e Laços. Os exemplos rodam na máquina fictícia notebook, com a usuária ana.

Definir e chamar

nome_da_funcao() {
  comandos
}

nome_da_funcao arg1 arg2
saudar()
O nome da função. Os parênteses vazios dizem "isto é uma função". Nunca se coloca nada dentro deles.
{
Abre o corpo da função.
echo "Olá, $1!"
O que a função faz. $1 é o primeiro argumento que ela recebeu.
}
Fecha o corpo.
#!/usr/bin/env bash
saudar() {
  echo "Olá, $1!"
}

saudar "Ana"
saudar "Bruno"
$ ./saudar.sh
Olá, Ana!
Olá, Bruno!
  • Definir a função não executa nada. Ela só roda quando é chamada.
  • A função precisa estar definida antes da linha que a chama, ou seja, mais acima no arquivo.
  • Para chamar, escreva o nome como um comando, sem parênteses: saudar "Ana".

Também funciona no terminal

Funções não são só para scripts. Você pode criar uma direto no terminal e ver como o Bash a enxerga:

$ diga_oi() { echo "oi"; }
$ diga_oi
oi
$ type diga_oi
diga_oi é uma função
diga_oi ()
{
    echo "oi"
}

Ela dura até você fechar o terminal. Para ter sempre, coloque no ~/.bashrc (veja .bashrc, alias, PATH).

Outra forma de escrever

O Bash também aceita function saudar { … }. Funciona igual, mas a forma saudar() { … } é a mais comum e também roda em outros shells.

Argumentos dentro da função

Dentro da função, $1, $2, $@ e $# são os argumentos da função, não os do script. Cada função recebe os seus.

O que a função devolve: echo ou return

Esta é a parte que mais confunde. Uma função pode devolver duas coisas diferentes:

echo (saída)return (código)
O que éTexto escrito na telaNúmero de 0 a 255, o código de saída
Para quêDevolver um resultado (um nome, uma soma)Dizer se deu certo (0) ou errado (outro)
Como pegarvalor=$(funcao)if funcao; then ou $?

Devolver um resultado com echo

#!/usr/bin/env bash
somar() {
  local resultado=$(( $1 + $2 ))
  echo "$resultado"
}

total=$(somar 7 5)
echo "O total é $total"
total=
Guarda na variável total…

)
Fecha a captura.
$ ./soma.sh

Responder "sim ou não" com o código

Uma função que só testa algo pode usar o código do último comando. Aqui, o código do [ -d ] vira o código da função:

#!/usr/bin/env bash
pasta_existe() {
  [ -d "$1" ]
}

if pasta_existe "Downloads"; then
  echo "Downloads existe"
fi

pasta_existe "Videos"
echo "Código devolvido para Videos: $?"
$ ./existe.sh
Downloads existe
Código devolvido para Videos: 1

Com return, você escolhe o código explicitamente: return 0 (sucesso) ou return 1 (falha). Sem return, a função devolve o código do último comando que rodou.

return não devolve texto nem números grandes

return 300 não devolve 300: o código só vai de 0 a 255, e 300 vira 44. Para devolver um valor, use echo.

$ f() { return 300; }
$ f; echo $?
44

Variáveis locais: local

Por padrão, uma variável criada dentro da função vale no script inteiro. Isso pode estragar uma variável de mesmo nome usada em outro lugar. Com local, ela só existe dentro da função.

#!/usr/bin/env bash
nome="global"

sem_local() { nome="mudei"; }
com_local() { local nome="só aqui dentro"; echo "dentro: $nome"; }

com_local
echo "depois de com_local: $nome"
sem_local
echo "depois de sem_local: $nome"
$ ./local.sh
dentro: só aqui dentro
depois de com_local: global                « o local não vazou
depois de sem_local: mudei                 « sem local, a variável de fora foi alterada
Regra prática

Toda variável criada dentro de uma função leva local, a não ser que você queira mesmo mudar uma variável do script.

Reaproveitar funções: source

Funções que você usa em vários scripts podem morar num arquivo separado, uma "biblioteca". O source (ou o atalho .) carrega esse arquivo dentro do script atual.

# lib.sh — funções reaproveitáveis (não precisa de shebang nem chmod +x)
info() { echo "[INFO] $*"; }
erro() { echo "[ERRO] $*" >&2; }
#!/usr/bin/env bash
source "$(dirname "$0")/lib.sh"

info "Começando o trabalho"
erro "Algo deu errado"
source
Lê o arquivo e executa no script atual, como se o conteúdo estivesse colado ali.
"$(dirname "$0")
A pasta onde o script está. Assim ele acha a lib.sh de qualquer lugar de onde for chamado.
/lib.sh"
O arquivo da biblioteca.
$ ./usa-lib.sh
[INFO] Começando o trabalho
[ERRO] Algo deu errado

Limpeza automática: trap

Scripts às vezes criam arquivos temporários. O trap ("armadilha") registra uma função para rodar quando o script termina, mesmo que termine por erro ou por Ctrl+C.

#!/usr/bin/env bash
tmp=$(mktemp -d)

limpar() {
  rm -rf "$tmp"
  echo "Pasta temporária apagada."
}
trap limpar EXIT

echo "Trabalhando em $tmp"
touch "$tmp/rascunho.txt"
exit 0
trap
Registra o que fazer quando algo acontecer.
limpar
A função que será chamada.
EXIT
Quando: na saída do script, por qualquer motivo.
$ ./temporario.sh
Trabalhando em /tmp/tmp.k3Q9xLmA2c
Pasta temporária apagada.

O mktemp -d cria uma pasta com nome aleatório em /tmp, então o nome muda a cada execução.

Exemplo completo: organizar a pasta Downloads

Este script separa os arquivos de uma pasta em subpastas por tipo. Cada função tem um trabalho: uso explica como usar, categoria decide o tipo, mover move um arquivo e main coordena tudo.

#!/usr/bin/env bash
# organizar.sh — separa os arquivos de uma pasta em subpastas por tipo
# Uso: ./organizar.sh [PASTA]   (padrão: ~/Downloads)

set -euo pipefail

pasta="${1:-$HOME/Downloads}"

uso() {
  echo "Uso: $0 [PASTA]" >&2
  exit 1
}

categoria() {
  case "${1,,}" in
    *.pdf|*.txt|*.odt|*.docx) echo "Documentos" ;;
    *.jpg|*.jpeg|*.png|*.gif) echo "Imagens" ;;
    *.mp3|*.ogg|*.flac)       echo "Musicas" ;;
    *.deb|*.zip|*.tar.gz)     echo "Instaladores" ;;
    *)                        echo "Outros" ;;
  esac
}

mover() {
  local arquivo="$1"
  local destino
  destino="$pasta/$(categoria "$arquivo")"
  mkdir -p "$destino"
  mv -n "$arquivo" "$destino/"
  echo "$(basename "$arquivo") -> $(basename "$destino")/"
}

main() {
  [ -d "$pasta" ] || uso
  local total=0
  for arquivo in "$pasta"/*; do
    [ -f "$arquivo" ] || continue
    mover "$arquivo"
    total=$((total + 1))
  done
  echo "Pronto: $total arquivo(s) organizados."
}

main

Os detalhes novos:

  • set -euo pipefail faz o script parar no primeiro erro (veja Primeiro Script).
  • ${1:-$HOME/Downloads} usa o primeiro argumento ou, se não houver, a pasta Downloads.
  • ${1,,} é o nome em letras minúsculas, para FOTO.JPG também cair em Imagens.
  • mv -n nunca sobrescreve um arquivo que já esteja no destino.
  • main no fim é a única linha "solta": todo o resto está em funções.

$ ./organizar.sh

Por que a ordem mudou?

O ls do Ubuntu 26.04 coloca maiúsculas antes (LEIAME primeiro). Já o curinga * do Bash segue a ordem do idioma português, sem separar maiúsculas, por isso LEIAME aparece entre foto.jpg e manual.pdf.

mkcd() { mkdir -p "$1" && cd "$1"; } cria uma pasta e já entra nela: mkcd projeto/novo. Um alias não conseguiria fazer isso, porque precisa usar o argumento duas vezes.

Quando não funciona

"comando não encontrado" ao chamar a função 
$ ./saudar.sh
./saudar.sh: linha 2: saudar: comando não encontrado

O que aconteceu: a chamada saudar "Ana" está acima da definição no arquivo. O Bash lê de cima para baixo e ainda não conhecia a função.

Como resolver: mova as definições para o topo e as chamadas para o fim. Ou use o padrão main no fim do arquivo.

O terminal mostra > depois de definir a função 
$ f() { echo oi }
>

O que aconteceu: numa linha só, o último comando antes do } precisa de ;. Sem ele, o Bash acha que o } é um argumento do echo e continua esperando o fechamento.

Como resolver: Ctrl+C e escreva f() { echo oi; }, com ; e espaço depois do {.

"local: somente pode ser usado em uma função" 
$ local x=1
bash: local: somente pode ser usado em uma função

O que aconteceu: local só existe dentro de funções.

Como resolver: fora de funções, crie a variável normalmente: x=1.

"return: possível retornar … apenas de uma função" 
$ return 1
bash: return: possível retornar (`return') apenas de uma função ou script carregado (com `source')

O que aconteceu: return sai de uma função. Para encerrar o script inteiro, o comando é outro.

Como resolver: no corpo principal do script, use exit 1.

Resumo

  • Defina com nome() { …; } antes de chamar; chame como um comando, sem parênteses.
  • $1, $@ e $# dentro da função são os argumentos dela.
  • echo devolve resultados (pegue com $(…)); return devolve só o código de 0 a 255.
  • Use local em toda variável da função.
  • source reaproveita bibliotecas; trap … EXIT garante a limpeza.
