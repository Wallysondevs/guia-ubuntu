Ubuntu Informações do Sistema

Qual é a versão do Ubuntu? Qual kernel está rodando? Quantos núcleos tem o processador? Qual é a placa de vídeo e que driver ela usa? Saber responder isso é o primeiro passo para instalar o driver certo, pedir ajuda num fórum ou planejar uma atualização de hardware.

Você vai aprender
  • A identificar versão do Ubuntu, kernel e modelo da máquina.
  • A ler a saída do lscpu e do free.
  • A listar placas e dispositivos com lspci, lsusb e lshw, e a ver o driver de cada um.
  • A montar um relatório seguro (sem dados pessoais) para colar num fórum.

Os exemplos são do notebook fictício da Ana: um notebook com processador AMD de 8 threads e 16 GB de RAM.

O resumo de tudo: hostnamectl

O hostnamectl serve para ver e mudar o nome da máquina, mas sem argumentos ele mostra um ótimo resumo:

$ hostnamectl

       Icon name: computer-laptop
         Chassis: laptop 💻                          « notebook, desktop, vm, server…
      Machine ID: 4b1f0c6e9a2d4c7f8e3a5b6c7d8e9f01
         Boot ID: 9c2e7a1b3d4f4e5a8b6c7d8e9f0a1b2c
Operating System: Ubuntu 26.04.1 LTS                 « versão do Ubuntu
          Kernel: Linux 7.0.0-38-generic             « versão do kernel
    Architecture: x86-64
 Hardware Vendor: Lenovo                             « fabricante
  Hardware Model: ThinkPad E14 Gen 5                 « modelo
Firmware Version: R2AET41W (1.21)                    « versão da BIOS/UEFI

O Machine ID é um identificador único desta instalação. Não é segredo grave, mas evite publicá-lo: ele identifica a sua máquina. Para mudar o nome da máquina, veja Configurar a Rede.

Versão do Ubuntu

Há três formas de perguntar, e cada uma é útil numa situação:

$ lsb_release -a
Distributor ID:	Ubuntu
Description:	Ubuntu 26.04.1 LTS
Release:	26.04
Codename:	resolute
$ lsb_release -sc
resolute
$ cat /etc/os-release
PRETTY_NAME="Ubuntu 26.04.1 LTS"
NAME="Ubuntu"
VERSION_ID="26.04"
VERSION="26.04.1 LTS (Resolute Raccoon)"
VERSION_CODENAME=resolute
ID=ubuntu
ID_LIKE=debian
…
lsb_release
Mostra a versão no padrão LSB (Linux Standard Base).
-s
Short: só o valor, sem o rótulo. Bom para scripts.
-c
Codename: o nome de código.

O codinome resolute vem de "Resolute Raccoon", o apelido do 26.04, e aparece nos endereços dos repositórios. O .1 de 26.04.1 é o point release: a mesma versão com as correções acumuladas. O /etc/os-release existe em qualquer distribuição Linux, por isso é o preferido em scripts: . /etc/os-release; echo $VERSION_ID.

Kernel: uname

O uname (de Unix name) informa o kernel, a parte central do sistema que conversa com o hardware.

$ uname -r
7.0.0-38-generic
$ uname -a
Linux notebook 7.0.0-38-generic #38-Ubuntu SMP PREEMPT_DYNAMIC Fri Sep  4 09:10:14 UTC 2026 x86_64 GNU/Linux
Pedaço de 7.0.0-38-genericSignificado

generic"Sabor" do kernel: o padrão para desktops e servidores.
OpçãoMostra

Quais kernels estão instalados, e como voltar para um anterior, você vê em Boot, GRUB e Kernel.

Processador: lscpu e nproc

$ lscpu | head -14
Arquitetura:                               x86_64
Modo(s) operacional da CPU:                32-bit, 64-bit
Tamanhos de endereço:                      48 bits physical, 48 bits virtual
Ordem dos bytes:                           Little Endian
CPU(s):                                    8                       « total de threads
Lista de CPU(s) on-line:                   0-7
ID de fornecedor:                          AuthenticAMD
Nome do modelo:                            AMD Ryzen 5 7520U with Radeon Graphics
Família da CPU:                            23
Modelo:                                    160
Thread(s) per núcleo:                      2
Núcleo(s) por soquete:                     4                       « núcleos físicos
Soquete(s):                                1
Step:                                      0
$ nproc
8

A conta é: 1 soquete × 4 núcleos × 2 threads por núcleo = 8 CPUs. Para o sistema, cada thread é uma "CPU". O nproc (de number of processors) mostra só esse número, útil em scripts como make -j$(nproc).

Para saber se o processador aceita máquinas virtuais (veja KVM e virt-manager):

$ lscpu | grep -i virtualiza
Virtualização:                             AMD-V                   « Intel mostra VT-x

Memória: free e dmidecode

$ free -h
               total       usada       livre    compart.  buff/cache  disponível
Mem.:           15Gi       4,7Gi       3,6Gi       118Mi       7,2Gi        10Gi
Swap:          4,0Gi          0B       4,0Gi

16 GB aparecem como 15Gi porque o -h usa a unidade binária (1 Gi = 1024 Mi) e parte da RAM fica reservada ao vídeo integrado. Olhe a coluna disponível; a explicação completa está em Desempenho e Monitoramento.

Para saber quantos pentes de memória há e se sobra slot livre para um upgrade, pergunte ao firmware com o dmidecode (precisa de sudo):

sudo dmidecode
Lê a tabela DMI/SMBIOS, que o fabricante grava na placa-mãe.
-t memory
Type: só a parte de memória.
| grep -E "Size|Speed|Locator"
Filtra só tamanho, velocidade e posição de cada slot.
$ sudo dmidecode -t memory | grep -E "^\s+(Size|Speed|Locator):"
	Size: 8 GB
	Locator: DIMM 0
	Speed: 5500 MT/s
	Size: 8 GB
	Locator: DIMM 1                                     « dois pentes de 8 GB, nenhum slot livre
	Speed: 5500 MT/s

O -e7 esconde os dispositivos loop (os snaps montados). Tudo sobre discos e espaço está em lsblk, df, du.

Placas e dispositivos: lspci, lsusb, lshw

lspci lista o que está ligado ao barramento PCI: placa de vídeo, rede cabeada, Wi-Fi, som. A pergunta mais comum é "qual é a minha placa de vídeo e qual driver ela usa?":

lspci
Lista os dispositivos PCI.
-k
Mostra o driver do kernel (kernel driver) de cada um.
| grep -A3 -i vga
Mostra a linha da placa de vídeo e as 3 seguintes (after).
$ lspci -k | grep -A3 -i vga
04:00.0 VGA compatible controller: Advanced Micro Devices, Inc. [AMD/ATI] Barcelo (rev c1)
	Subsystem: Lenovo Device 3f4b
	Kernel driver in use: amdgpu                         « o driver que está funcionando
	Kernel modules: amdgpu

Se faltar a linha Kernel driver in use, o dispositivo está sem driver. É o primeiro sinal de "Wi-Fi não aparece" ou "vídeo travado em baixa resolução". Para a rede:

$ lspci | grep -Ei "network|ethernet"
02:00.0 Network controller: MEDIATEK Corp. MT7922 802.11ax PCI Express Wireless Network Adapter
03:00.0 Ethernet controller: Realtek Semiconductor Co., Ltd. RTL8111/8168/8211/8411 PCI Express Gigabit Ethernet Controller (rev 15)

O lsusb faz o mesmo para dispositivos USB:

$ lsusb
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 001 Device 003: ID 046d:c52b Logitech, Inc. Unifying Receiver      « o receptor do mouse
Bus 003 Device 002: ID 0e8d:0616 MediaTek Inc. Wireless_Device         « o Bluetooth

O par 046d:c52b é a identidade do aparelho: fabricante (046d = Logitech) e modelo. Procurar esse código na internet é a melhor forma de achar informações sobre drivers.

Quando não funciona

"comando não encontrado" 
$ sensors
Comando 'sensors' não encontrado, mas poder ser instalado com:
sudo apt install lm-sensors

O que aconteceu: a ferramenta não vem instalada. O Ubuntu sugere o pacote certo (o "poder" é um erro da tradução original).

Como resolver: rode o comando sugerido.

dmidecode sem sudo 
$ dmidecode -t memory
# dmidecode 3.6
/sys/firmware/dmi/tables/smbios_entry_point: Permission denied
Scanning /dev/mem for entry point.

O que aconteceu: a tabela do firmware só pode ser lida pelo root.

Como resolver: sudo dmidecode -t memory.

O dispositivo aparece no lspci, mas não funciona 
$ lspci -k | grep -A3 -i network
02:00.0 Network controller: MEDIATEK Corp. MT7922 802.11ax PCI Express Wireless Network Adapter
	Subsystem: Lenovo Device e0e0
	Kernel modules: mt7921e                              « falta "Kernel driver in use"

O que aconteceu: o kernel conhece um driver (Kernel modules), mas ele não está carregado.

Como resolver: veja o motivo no log do kernel com sudo dmesg | grep -i mt7921. Muitas vezes falta firmware (pacote linux-firmware) ou o kernel é antigo. Atualize o sistema e reinicie.

Resumo

  • hostnamectl resume sistema, kernel e modelo; lsb_release -a e /etc/os-release dão a versão.
  • uname -r = kernel; lscpu/nproc = processador; free -h = memória.
  • lspci -k mostra placas e drivers; sem "Kernel driver in use", o dispositivo está sem driver.
  • lsusb lista USB; o código fabricante:modelo ajuda a achar drivers.
  • Para fóruns, use inxi -Fxz, que esconde dados pessoais.
