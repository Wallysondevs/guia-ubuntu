Ubuntu Particionar e Formatar

Um disco novo chega "cru": o Ubuntu enxerga o aparelho, mas não consegue guardar arquivos nele. Para usar, você faz três coisas: cria uma tabela de partições, cria uma ou mais partições e formata cada partição com um sistema de arquivos. Nesta aula você faz tudo isso com fdisk, parted e mkfs.

Esta aula apaga dados

Particionar e formatar destroem o que estiver no disco, sem lixeira e sem "desfazer". Pratique primeiro no laboratório seguro mostrado abaixo. Num disco real, confira o nome do dispositivo duas vezes antes de apertar Enter.

Você vai aprender
  • A diferença entre disco, tabela de partições, partição e sistema de arquivos.
  • Como montar um laboratório sem risco com arquivos-imagem.
  • Como identificar o disco certo com lsblk.
  • Particionar com fdisk (interativo) e com parted (numa linha só).
  • Formatar com mkfs.ext4 e outros formatos, e criar swap.

Os exemplos acontecem na máquina fictícia servidor, com a usuária ana. O disco do sistema é o /dev/sda e o disco novo é o /dev/sdb.

Conceito: o terreno, os lotes e a casa

Pense num disco como um terreno. Antes de construir, é preciso registrar o mapa dos lotes, depois dividir o terreno em lotes e, por fim, construir em cada lote.

GPT ou MBR?

Nomes dos dispositivos

  • /dev/sda, /dev/sdb…: discos SATA, USB e discos de VM. As partições ganham um número: /dev/sdb1, /dev/sdb2.
  • /dev/nvme0n1, /dev/nvme1n1…: SSDs NVMe. As partições ganham p + número: /dev/nvme1n1p1.
  • /dev/vda: disco virtual em algumas VMs (KVM).
  • /dev/loop0…: "discos" que são arquivos. Os snaps usam vários; ignore-os.

Laboratório seguro: um disco que é só um arquivo

O fdisk, o parted e o mkfs aceitam um arquivo comum no lugar de um disco. Assim você treina tudo sem sudo e sem chance de estragar nada. Comece criando um "disco" de 10 GB:

truncate
Programa que muda o tamanho de um arquivo.
-s 10G
-s (size) define o tamanho: 10 GB.
disco.img
O arquivo que vai fazer o papel de disco.
$ truncate -s 10G disco.img
$ ls -lh disco.img
-rw-rw-r-- 1 ana ana 10G Oct 15 10:30 disco.img       « parece ter 10 GB…
$ du -h disco.img
0       disco.img                                     « …mas não ocupa nada ainda

O arquivo é "esparso": o espaço só é gasto quando algo é gravado. Tudo o que você fizer a seguir com /dev/sdb pode ser feito trocando /dev/sdb por disco.img e tirando o sudo.

Outra opção: uma VM com disco extra

No VirtualBox, em Configurações → Armazenamento, adicione um segundo disco virtual. Dentro da VM ele aparece como /dev/sdb, igual a um disco de verdade. Se algo der errado, só a VM sofre.

Passo 1: identificar o disco certo

Antes de qualquer coisa, descubra o nome do disco novo. O erro mais grave desta aula é formatar o disco do sistema por engano.

lsblk
"list block devices": lista discos e partições.
-o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL
Escolhe as colunas: nome, tamanho, tipo, formato, onde está montado e modelo.
-e 7
Esconde os dispositivos do tipo 7 (os loop dos snaps).
$ lsblk -e 7 -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL
NAME     SIZE TYPE FSTYPE MOUNTPOINTS MODEL
sda       64G disk                    QEMU HARDDISK
├─sda1     1G part vfat   /boot/efi                    « disco do sistema: NÃO mexa
└─sda2    63G part ext4   /
sdb      100G disk                    QEMU HARDDISK    « o novo: sem partições, sem montagem

Como reconhecer o disco novo:

  • Tem o tamanho que você comprou ou criou.
  • Não tem linhas de partição (├─) embaixo dele.
  • A coluna MOUNTPOINTS está vazia.
Confirme pelo antes e depois

Rode lsblk antes de ligar o disco (ou o pendrive) e de novo depois. O nome que apareceu é o novo.

Passo 2: particionar com fdisk

fdisk (de fixed disk) é interativo: você digita uma letra por vez, e ele pergunta o resto. Nada é gravado até você digitar w. Se errar, digite q para sair sem salvar.

sudo
Mexer em discos exige administrador. No laboratório com arquivo, não precisa.
fdisk
O programa de particionamento.
/dev/sdb
O disco inteiro (sem número no fim). No laboratório: disco.img.

Entendendo a pergunta do "último setor": o disco é dividido em setores de 512 bytes. Em vez de calcular setores, você escreve o tamanho com +: +4G significa "4 GB a partir do início". Deixar em branco usa todo o espaço livre.

O que o comando devolve

O fdisk não altera o disco até o w. Se você sair com q, o código de saída é 0 e nada mudou. Se ele não conseguir reler a tabela (o disco está em uso), mostra Releitura da tabela de partição falhou.; nesse caso, rode sudo partprobe /dev/sdb ou reinicie.

Forma alternativa: parted numa linha só

O parted faz o mesmo trabalho, mas aceita tudo como argumentos. É a forma preferida em scripts, porque não exige ninguém digitando.

sudo parted
O programa, como administrador.
-s
script: não faz perguntas.
/dev/sdb
O disco inteiro.
mklabel gpt
Cria uma tabela GPT nova (apaga a anterior).
mkpart dados ext4 0% 100%
Cria uma partição chamada "dados", marcada como ext4, do início (0%) ao fim (100%).
print
Mostra o resultado.
$ sudo parted -s /dev/sdb mklabel gpt mkpart dados ext4 0% 100% print
Modelo: QEMU QEMU HARDDISK (scsi)
Disco /dev/sdb: 107GB
Tamanho do setor (lógico/físico): 512B/512B
Tabela de Partição: gpt
Opções de disco:

Número  Início  Fim    Tamanho  Sistema de arquivos  Nome   Opções
 1      1049kB  107GB  107GB                         dados          « ainda sem formato
O "ext4" do mkpart não formata

No mkpart, o tipo é só uma etiqueta na tabela. A partição continua vazia até você rodar o mkfs. Usar 0% e 100% faz o parted alinhar a partição corretamente, sem você calcular setores.

Passo 3: formatar com mkfs

mkfs vem de make filesystem, "criar sistema de arquivos". Existe uma versão para cada formato: mkfs.ext4, mkfs.xfs, mkfs.vfat…

sudo mkfs.ext4
Cria um sistema de arquivos ext4 (o padrão do Ubuntu).
-L dados
-L (label) dá um nome à partição. Aparece no lsblk -f e no gerenciador de arquivos.
/dev/sdb2
A partição (com número no fim), não o disco.
$ sudo mkfs.ext4 -L dados /dev/sdb2

A tradução mistura português de Portugal ("ficheiros", "A criar") e do Brasil: é assim que o mke2fs aparece no Ubuntu 26.04. O que importa:

  • UUID: o "RG" da partição. É ele que você usa no /etc/fstab (veja mount e fstab).
  • Cópias de superblocos: backups da estrutura do disco, usados pelo fsck para consertar danos.
  • Diário (journal): registro que protege contra corrupção em quedas de energia.

Apagar assinaturas antigas: wipefs

Um disco reaproveitado pode ter restos de formatos antigos (RAID, LVM, ZFS) que confundem o sistema. wipefs (de wipe filesystem signatures) lista e apaga essas "assinaturas".

$ sudo wipefs /dev/sdb                    « só lista, não apaga
DEVICE OFFSET       TYPE UUID LABEL
sdb    0x200        gpt
sdb    0x18fffffe00 gpt
sdb    0x1fe        PMBR
$ sudo wipefs -a /dev/sdb                 « -a (all) apaga todas
/dev/sdb: 8 bytes foram apagados na posição 0x00000200 (gpt): 45 46 49 20 50 41 52 54
/dev/sdb: 8 bytes foram apagados na posição 0x18fffffe00 (gpt): 45 46 49 20 50 41 52 54
/dev/sdb: 2 bytes foram apagados na posição 0x000001fe (PMBR): 55 aa
Atenção

wipefs -a faz o disco "esquecer" todas as partições na hora. Os dados ainda estão lá fisicamente, mas o sistema deixa de enxergá-los.

Swap: memória extra no disco

Swap é um espaço no disco que o Linux usa quando a memória RAM enche. É bem mais lento que a RAM, mas evita que programas sejam encerrados à força. O Ubuntu cria um arquivo /swap.img na instalação. Veja como está:

$ swapon --show
NAME      TYPE SIZE USED PRIO
/swap.img file   4G 512M   -2                « arquivo de 4 GB, 512 MB em uso

Criar um arquivo de swap

  1. Reserve o espaço. fallocate -l 8G cria um arquivo de 8 GB de uma vez. 
    $ sudo fallocate -l 8G /swapfile
  2. Proteja o arquivo. Só o root pode ler: a swap pode conter senhas que estavam na memória. 
    $ sudo chmod 600 /swapfile
  3. Formate como swap e ative. 
    $ sudo mkswap /swapfile
Configurando espaço de swap versão 1, tamanho = 8 GiB (8589930496 bytes)
nenhum rótulo, UUID=6b0f3c2e-1a7d-4f5b-9c8e-2d4a6f8b0c1e
$ sudo swapon /swapfile
$ swapon --show
NAME      TYPE SIZE USED PRIO
/swap.img file   4G 512M   -2
/swapfile file   8G   0B   -3                « a nova swap
  4. Torne permanente. Adicione a linha no /etc/fstab para ela voltar após reiniciar: 
    $ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
/swapfile none swap sw 0 0

Quanto o sistema usa a swap: vm.swappiness

Um número de 0 a 200. O padrão é 60. Valores menores fazem o Linux preferir a RAM e usar a swap só quando necessário.

$ cat /proc/sys/vm/swappiness
60
$ echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swappiness.conf
vm.swappiness=10
$ sudo sysctl --system | tail -1
vm.swappiness = 10

Quando não funciona

"is mounted; will not make a filesystem here!" 
$ sudo mkfs.ext4 /dev/sdb2
mke2fs 1.47.2 (1-Jan-2025)
/dev/sdb2 is mounted; will not make a filesystem here!

O que aconteceu: a partição está montada (em uso). O mkfs se recusa a formatar, para proteger seus dados.

Como confirmar: findmnt /dev/sdb2 mostra onde ela está montada.

Como resolver: se for mesmo a partição certa, desmonte com sudo umount /dev/sdb2 e rode de novo. Esse erro também é um bom momento para conferir se você não digitou o disco errado.

"contains a ext4 file system … Proceder mesmo assim?" 
$ sudo mkfs.ext4 /dev/sdb2
mke2fs 1.47.2 (1-Jan-2025)
/dev/sdb2 contains a ext4 file system labelled 'dados'
	last mounted on /mnt/dados on Wed Oct 14 18:02:11 2026
Proceder mesmo assim? (y,N)

O que aconteceu: já existe um sistema de arquivos ali, possivelmente com dados. O padrão (N) cancela.

Como resolver: responda y só se tiver certeza de que pode apagar tudo. A data do "last mounted" ajuda a lembrar o que havia ali.

"O ficheiro … não existe e não foi especificado um tamanho." 
$ sudo mkfs.ext4 /dev/sdb3
mke2fs 1.47.2 (1-Jan-2025)
O ficheiro /dev/sdb3 não existe e não foi especificado um tamanho.

O que aconteceu: a partição sdb3 não existe. Ou você errou o número, ou ela ainda não foi criada.

Como resolver: confira com lsblk /dev/sdb. Se as partições acabaram de ser criadas e não aparecem, rode sudo partprobe /dev/sdb.

Formatou o disco inteiro em vez da partição

O que aconteceu: rodou mkfs.ext4 /dev/sdb (sem número). Funciona, mas apaga a tabela de partições: o disco vira um sistema de arquivos só, sem partições.

Como resolver: se não há dados ainda, recomece: sudo wipefs -a /dev/sdb e particione de novo. Regra prática: fdisk e parted recebem o disco (/dev/sdb); mkfs recebe a partição (/dev/sdb1).

Resumo

  • Ordem: tabela (GPT) → partição → formato (mkfs) → montagem.
  • Identifique o disco com lsblk antes de tudo; o disco novo não tem partições nem montagem.
  • fdisk é interativo e só grava no w; q sai sem mudar nada. parted -s faz tudo numa linha.
  • fdisk/parted recebem o disco (/dev/sdb); mkfs recebe a partição (/dev/sdb1).
  • Treine com truncate -s 10G disco.img: as mesmas ferramentas funcionam num arquivo, sem risco.
